## What changed

### #629 IPFS evidence durability policy (`docs/ipfs-evidence-durability.md`)

- Policy plus current implementation for pinning (Pinata, CIDv1), replication, gateway fallback (the real race/quarantine pool in `ipfsGateway.js` and its settings), encryption and privacy (AES-256-GCM, crypto-shredding for erasure), retention (24 months after final resolution, legal hold), deletion and GC rules, SLAs, verification steps (hash/Merkle check, weekly pin audit script), and a configuration reference.
- **Known gaps found in the code** (listed in the doc, not fixed here):
  1. Decryption keys live only in an in-process `Map`, so a restart makes all evidence undecryptable.
  2. `fileUpload.js` calls `ipfsService.pinFile(file.buffer)` without a MIME type, so `validateFile` rejects every evidence file upload (`500 IPFS upload failed`).
  3. No authorised addresses are recorded for a CID, so `getDecryptionKey` would refuse every caller.
  4. `file_hash` / `merkle_root` are never stored, so verification always reports "No stored hash".
  5. The GC's 24 h safety buffer never applies (it only looks up upload time for CIDs with no evidence row), so the daily 04:00 UTC run unpins anything unreferenced, including in-flight uploads and other content on the same Pinata account.
  6. Single pinning provider. 7. `verifyEvidence` is not mounted on any route. 8. No retention clock, legal hold, or key destruction.

### #631 Contract event developer checklist (`docs/contract-event-checklist.md`)

- End-to-end checklist (copy-paste block for PRs) covering the `event_names.rs` constant (9-char `symbol_short!` limit), the `events.rs` emitter, payload and negative tests in `event_tests.rs`, the `event-schema.md` row, the indexer `dispatchEvent` case with the idempotent `contractEvent.upsert`, **indexer replay validation** (rewinding `indexer_state.last_processed_ledger`, duplicate check query, RPC retention limits), OpenAPI (`paths/events.js`), and frontend/mobile consumers.
- New ratchet test `backend/tests/contractEventDocs.test.js`: every constant in `event_names.rs` must be documented in `docs/event-schema.md`. The 43 constants that are undocumented today are an allowlist that may only shrink: a new undocumented event fails, and so does an allowlisted event that has since been documented. Probed both directions.
- Gaps noted: 43/73 event constants undocumented; 4 inline `symbol_short!` topics in `events.rs`; the indexer handles 9 topics and drops the rest; the OpenAPI `eventType` example (`escrow_created`) does not match stored topic symbols; `escrowIndexer.test.js` is excluded in `jest.config.js`.

### #632 Announcement targeting docs (`docs/announcements.md`)

- Data model, endpoints, target rules (`all` / `tenant` + tenant existence check), inclusive active windows, ordering (`startsAt` desc), soft delete, tenant scoping (always resolved by `tenantMiddleware`), admin `curl` examples (scheduled global notice, tenant notice, end early, widen to all, delete), and an edge-case table for overlapping announcements, partial updates, deletion and validation errors.
- Documented as not supported: priority/severity, server-side dismissal (with a client-side dismissal pattern keyed by `id` + `updatedAt`), multi-tenant/role targeting, an admin list endpoint, and authenticated authorship (`createdBy` is taken from the body). No frontend or mobile code consumes the endpoint yet.

### #636 Mobile cache schema version (`mobile/services/offlineCache.ts`)

- Every cached row now has a `schema_version` column. `initOfflineDb` creates it for new installs and adds it to existing databases with `ALTER TABLE … DEFAULT 1`, so rows written before versioning read as version 1 (the current payload format).
- Writes (`cacheEscrow`, `cacheMilestones`) stamp `CACHE_SCHEMA_VERSION`. Reads go through `migrateRecord`: the current version passes through, older versions run the `CACHE_MIGRATIONS` chain and are rewritten at the current version, and rows with a gap in the chain, a newer version (written by a later build), or corrupted JSON are deleted and skipped.
- **Pre-existing breakage:** merged PR #1016 (`334a71c`) left `offlineCache.ts` as two concatenated implementations (two databases, duplicate exports, an unclosed function: 125 `tsc` errors). This file had to be rebuilt to add versioning. It keeps the API the app uses (`initOfflineDb` in `_layout.tsx`, escrows + milestones in `ste_offline.db`, the `Escrow` type) and folds in #1016's per-entity TTLs (escrow via `EXPO_PUBLIC_OFFLINE_CACHE_TTL_MS`, milestones 2 min) and its foreground cleanup listener (`pruneStaleCache`, `start/stopCacheCleanupListener`, `clearAllCache`).
- **Not changed (out of scope, still broken on `develop`):** #1016 left the same concatenation in `mobile/hooks/useEscrows.ts` (two `useEscrowList` definitions) and `mobile/app/escrow/[id].tsx` (two default exports). They still fail `tsc` exactly as on `develop`.
